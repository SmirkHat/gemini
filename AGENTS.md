# AGENTS.md — SmirkHat.org Template

This document is the authoritative instruction set for any AI agent (Cursor, Claude, Copilot, or others) working in this repository or in any project derived from this template. Follow these directives strictly. When a user request conflicts with this document, point out the conflict before proceeding.

## 1. Project Identity

This repository belongs to the **SmirkHat.org** ecosystem — a Czech IT geek community focused on **open-source**, **self-hosting**, and **minimalistic web utilities**.

- Projects are small, focused tools. Do not add features, dependencies, or abstractions beyond what the task requires.
- User-facing copy is written in **Czech** unless explicitly stated otherwise. Set `lang="cs"` on the document.
- Attribution, contact, and links point to [smirkhat.org](https://smirkhat.org) and [github.com/SmirkHat](https://github.com/SmirkHat).
- **Every tool keeps the footer attribution** („Vytvořeno SmirkHat.org" with a link to smirkhat.org, see `src/components/footer.tsx`). Never remove it when redesigning a page.

## 2. Tech Stack (strict)

Do not introduce alternative frameworks, styling systems, or icon sets.

| Concern | Required technology |
| --- | --- |
| Framework | **TanStack Start** (React 19), file-based routing in `src/routes/` |
| Language | **TypeScript**, strict mode — no `any`, no `@ts-ignore` without justification |
| Styling | **Tailwind CSS** (latest, CSS-first config in `src/styles/app.css`) |
| UI components | **shadcn/ui**, New York style, in `src/components/ui/` |
| Icons | **Lucide** (`lucide-react`) only |
| Fonts | **Geist** and **Geist Mono** (self-hosted via Fontsource) |
| Package manager | **pnpm** only (enforced via `preinstall`) — never commit `package-lock.json` or `yarn.lock` |

- New shadcn components are added via the shadcn CLI (configuration lives in `components.json`) or written by hand in the same style.
- `src/routeTree.gen.ts` is generated by the router plugin. Never edit it by hand; it is gitignored.

## 3. Progressive Enhancement & SSR (non-negotiable)

SmirkHat projects must serve Tor users, users with strict privacy settings, and search engine crawlers. Therefore:

- **Core functionality, routing, and basic forms MUST work without client-side JavaScript.** Every page must render meaningful, complete HTML on the server.
- Prefer **URL-based state** (path params, search params) and **standard HTML** (`<a>`, `<form>`, `<details>`, native inputs) over client-side state and JS-driven widgets.
- Client-side JavaScript is an **enhancement layer only** (e.g. the theme override toggle). A feature that is unusable without JS is a defect unless it is technically impossible otherwise (e.g. canvas-based tools) — and even then, provide a `<noscript>` explanation.
- Do not add client-side analytics, tracking, or third-party scripts. Do not load assets from third-party CDNs; self-host everything.

## 4. Brand Tokens & Styling (strict)

Use only the SmirkHat design tokens defined in `src/styles/app.css`. Never hardcode colors in components — always use the semantic Tailwind classes (`bg-background`, `text-primary`, `border-border`, …).

- **Font:** Geist for text (`font-sans`), Geist Mono for code (`font-mono`).
- **Primary color:** Amber — `#f59e0b` in dark mode, `#d97706` in light mode. Mapped to the standard shadcn `--primary` variables.
- **Backgrounds:** Dark mode base `#171717`, cards `#222222`. Light mode warm off-white `#f7f7f5`, cards `#ffffff`.
- **Border radius:** `0.75rem` (`--radius`) for standard components. Use the `rounded-lg`/`rounded-md`/`rounded-sm` scale derived from it.
- Keep visual language minimal: subtle shadows, `primary/10` tinted accents, restrained animation. Always respect `prefers-reduced-motion`.

## 5. Theming (system-first, required)

- The **baseline** theme mechanism is pure CSS: `@media (prefers-color-scheme: dark)` switches the token set with **zero JavaScript and zero FOUC**.
- An explicit `.light` / `.dark` class on `<html>` acts as a user override, applied before first paint by the inline script in `src/routes/__root.tsx` and toggled by `src/components/theme-toggle.tsx`.
- The `dark:` Tailwind variant is defined in `app.css` to respect **both** mechanisms. Do not replace this setup with a JS-only theming library (no `next-themes` or similar).
- When adding tokens, define them in all three places: `:root` (light), the `prefers-color-scheme: dark` block, and `:root.dark`.

## 6. Code Quality

- **TypeScript:** strict, fully typed public APIs, no unchecked index access regressions. Prefer `type` inference over redundant annotations.
- **Accessibility (a11y):** semantic landmarks (`header`, `nav`, `main`, `footer`), exactly one `<h1>` per page, labelled interactive controls (`aria-label` where text is absent), visible focus states, and WCAG AA color contrast. The skip-link in the root layout must remain.
- **SEO:** every route defines its `head()` (title, description). The root route owns the defaults (OpenGraph, Twitter Cards, `author`, `rel="me"`).
- **Components:** small, composable, server-renderable by default. Reach for client-side interactivity only when needed.
- Comments explain non-obvious intent only. Do not narrate code.
- Before finishing any task, run `pnpm typecheck` and ensure `pnpm build` passes.
